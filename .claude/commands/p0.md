# P0. 기존 프로젝트 점검과 CLAUDE.md (단계 0)

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

이 폴더는 소방관 직원교육용 RTS 훈련게임의 Godot 4 프로젝트이고, 아파트 맵 일부가 구현돼 있다.
기획안은 docs/design.md 에 있다. 먼저 기획안을 끝까지 읽어라.

작업 1 (코드 수정 금지, 보고만):
- project.godot 에서 Godot 버전, 렌더러, 해상도 설정을 확인해라.
- 모든 씬(.tscn), 스크립트(.gd), 리소스를 목록화하고 각각 무엇을 하는지 한 줄씩 요약해라.
- 현재 구현이 탑다운인지 아이소메트릭인지, 2D인지 3D인지 확인해라.
- 기획안 9-5 기술 사양(Compatibility 렌더러, GDScript 정적 타입, JSON 데이터, 시뮬과 화면 분리)과 다른 점을 표로 정리해라.
- 살릴 것 / 고칠 것 / 버릴 것을 제안하고 docs/audit.md 로 저장해라.

작업 2 (내가 보고서를 승인한 뒤):
- 루트에 CLAUDE.md 를 만들어라. 내용: 게임 한 줄 설명, 폴더 구조, 코드 규칙(아래), 테스트 실행 방법, 기획안 위치.
- 코드 규칙:
  1) 렌더러는 Compatibility, 3D 노드 금지, 실시간 광원·그림자 금지.
  2) GDScript 정적 타입 필수, 주석은 한국어.
  3) 시뮬레이션 코드(scripts/sim/)는 Node를 상속하지 않는 순수 클래스(RefCounted)로 작성하고 화면 코드를 참조하지 않는다.
  4) 수치·카드·유닛·스테이지는 res://data/*.json 에만 둔다. 코드에 숫자를 박지 않는다.
  5) 모든 수치에는 source 필드(교재 근거 / 공학 표준 / 게임 설정값)를 붙인다.
  6) 시스템 간 통신은 EventBus 오토로드 시그널로 한다.
  7) 작업 단위마다 tests/ 에 headless 테스트를 추가하고 godot --headless -s tests/run_all.gd 로 통과시킨 뒤 커밋한다.
- 폴더 구조를 만들고 기존 파일을 옮겨라: autoload/, scripts/sim/, scripts/units/, scripts/cards/, scripts/ui/, scenes/, data/, maps/, tests/, docs/.
- 오토로드 뼈대: EventBus, DataDB(데이터 로드), SimClock(고정 주기: 화재 5Hz, 대원 10Hz, 현장 배속 time_scale 지원. 현장 시간과 UI용 실제 시간을 분리), GameState.
- tests/run_all.gd 와 샘플 테스트 1개.
- 기존 아파트 씬이 새 구조에서 에러 없이 열리는지 확인해라.
완료 기준: 테스트 통과, 에디터 경고 0, 커밋 "P0: 프로젝트 구조 정리".

작업이 끝나면 docs/progress.md 에 이 프롬프트 번호, 바뀐 파일, 남은 문제를 한 줄씩 추가해라.
