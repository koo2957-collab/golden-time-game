# P1. 데이터 스키마와 DataDB (단계 0)

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

CLAUDE.md 와 docs/design.md 5~7장을 읽어라.
res://data/ 에 아래 JSON 파일과 각 파일의 스키마 설명(docs/data_schema.md)을 만들어라.
- params.json: 시뮬 수치. 기획안 5장의 표 값을 그대로 넣고 각 값에 {value, unit, source} 를 둔다.
  예: flashover_temp_c 500 (소방전술3 연소이론), scba 충전압력 300, 경보압력 55, 용기 6.8, 활동별 호흡량,
  CO 농도별 사망시간 표, 산소농도 임계값(18%, 15%, 10%), FGI 대피 350℃, t² 화재 α(보통·빠름·매우빠름).
- vehicles.json, roles.json, equipment.json: 기획안 6장 표.
- crews.json: 기획안 6-1 출동대 기본 편성(선착대 5, 구조대 4, 구급대 3, 후착분대 5, 물탱크·사다리차 등 운전원 1).
  사용자가 고치지 않으면 이 값을 쓴다. 구조대·후착분대 팀장은 선착대장이 있으면 분대원 역할.
- cards/*.json: 기획안 7-1 구조. 우선 7-3 표의 카드를 모두 입력하되 effect 는 문자열 키로만 둔다.
- stages.json: 기획안 4장 표(스테이지 id, 이름, SOP, 역할, 해금 조건).
DataDB 오토로드는 시작 시 전부 읽고, 필수 필드가 없거나 타입이 틀리면 파일명과 항목을 담은 에러를 낸다.
테스트: 모든 JSON 검증 통과, 일부러 깨뜨린 파일을 넣으면 검증 실패.
계획을 먼저 보여주고 승인 후 구현해라.

작업이 끝나면 docs/progress.md 에 이 프롬프트 번호, 바뀐 파일, 남은 문제를 한 줄씩 추가해라.
