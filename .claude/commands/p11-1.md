# P11-1. 종료 조건·게임 메뉴·나가기 (단계 6, 기존 프로젝트 수정용)

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

docs/design.md 8-3, 8-4 를 읽어라.

[1. 종료 조건] 시나리오 제한시간이 있다면 없앤다. 대신 MissionEndChecker 를 만든다.
- 작전 완료: 모든 구획 화재 없음 + 잔불정리 완료 + 미검색 구역 없음 상태에서 지휘관이 '상황 종료' 선언.
- 전소: 화재 건물 가연물이 모두 소진되어 불이 꺼짐, 또는 구조 붕괴 비율이 params 기준 이상. '전소' 결과로 디브리핑.
  전소가 확실해지면(주요 구획 최성기·쇠퇴기 + 방수 없음) '결과 보기' 버튼으로 나머지를 화면 없이 빨리 계산.
- 지휘관 상황 종료 선언: 언제든 가능(상황 배지 메뉴). 완진 전·미검색 구역이 있으면 경고 후 확인.
- 화재 종료 후 현장 시간 10분 동안 변화가 없으면 '상황을 종료할까요?' 알림(강제 종료 아님).
- 대원 사망은 종료 조건이 아니다.

[2. 게임 메뉴(Esc)]
- 항목: 계속하기 / 조작 도움말 / 설정 / 처음부터 다시 / 임무 포기 / 메인 메뉴로 / 게임 종료.
  다시·포기·메인·종료는 확인 창을 거친다.
- 메뉴가 열리면 get_tree().paused = true(메뉴 노드는 PROCESS_MODE_WHEN_PAUSED), 지도와 질문 카드는 흐릿하게 가린다.
  일시정지 횟수는 DecisionLog 에 기록만 한다. Esc 는 마우스 가둠(CONFINED)도 푼다.
- 창 닫기(X)·Alt+F4: get_tree().set_auto_accept_quit(false) 로 막고 NOTIFICATION_WM_CLOSE_REQUEST 에서 '게임 종료' 확인 창을 띄운다.
- 임무 포기·메인·종료로 나가면 그때까지의 기록을 '미완료'로 저장한다.

[3. 화면 흐름]
- 타이틀 → 프로필 → 스테이지 선택 → 출동 → 현장 → 디브리핑 → 다시하기/다음/메인.
- 타이틀·스테이지 선택 화면에도 '게임 종료' 버튼.

테스트: 전소 시나리오(방수 없이 방치)가 자동 종료됨, 완진 후 선언으로 종료, Esc 메뉴에서 시뮬이 멈춤,
X 버튼에 확인 창이 뜨고 취소하면 게임 계속, 중도 종료 시 미완료 기록 저장.
계획 먼저 보여주고 승인 후 구현.

작업이 끝나면 docs/progress.md 에 이 프롬프트 번호, 바뀐 파일, 남은 문제를 한 줄씩 추가해라.
