# P2-2. 층·세대별 구조 변형과 집기 배치 (단계 1 보강, 기존 프로젝트 수정용)

> 사람용 메모(실행 전에 사람이 할 일):
> P2·P2-1이 끝난 프로젝트에 넣습니다. P3-1(화재 보강)보다 먼저 하면 가연물 데이터를 한 번에 쓸 수 있습니다.

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

docs/design.md 4-2, 4-2-1, 9-1(도면·시야), 5-2-1(가연물) 을 읽어라.
현재 아파트 맵이 층마다 똑같이 복사돼 있는지, 가구·가연물이 어떻게 들어 있는지 먼저 보고하고
(CLAUDE.md 비교 표) 계획을 승인받아라.

[1. 데이터 4단계]
- data/buildings/*.json: 동(층수, 계단실·승강로·샤프트, 층별 세대 타입 배치).
- data/unit_types/*.json: 세대 타입 표준 평면(방·문·창·발코니). 1층·최상층 별도 타입 가능.
- data/unit_variants/*.json: 타입별 변형(발코니 확장, 벽 철거, 피난시설 상태, 현관문 잠김·도어체크)을 "표준 평면에 대한 차이(벽 추가/제거, 문 상태)"로 저장.
- data/furnishings/*.json: 집기 세트(일반, 노인 1인, 짐 많음, 공실, 리모델링 중). 가구마다 재질·가연물량(MJ)·α등급·크기·통과(가능/느림/막힘)·숨은 잔화 계수·요구조자 숨는 장소 가중치.
- 스테이지: 동 + seed. seed 로 세대별 (변형, 집기 세트)를 고른다. 교관이 특정 세대를 직접 지정하면 그것이 우선. 같은 seed 는 항상 같은 맵(리플레이용 명령 로그와 함께 저장).

[2. 맵 조립]
- 로드 시 표준 평면 + 변형 차이 + 가구를 합쳐 층별 타일·구획실 데이터를 만든다. 구획실 가연물량·α는 가구 합으로 계산(화재 엔진에 전달).
- 가구는 노드가 아니라 데이터. 경로탐색 비용 격자(느림/막힘)에 반영하고 보는 층만 그린다. 그림은 data/art.json 매핑, 없으면 도형.

[3. 지휘관이 아는 정보]
- 도면(FloorPlanIntel)은 표준 타입만. 변형·가구는 대원이 본 뒤에만 KnowledgeBoard 에 들어간다.
- 새 임무 '직하층 확인'(data/commands.json): 팀이 지정 세대 바로 아래 세대를 돌며 본 구조를, 전술상황판에서 위 세대의 "추정 구조"(점선)로 표시.
  실제와 다르면 들어간 대원이 무전 보고(radio_lines.json: "구조가 다릅니다 - 발코니 확장" 등)하고 추정 구조를 덮어쓴다.
- 밖에서 보이는 단서(실내등 점등, 도어체크)를 세대 데이터에서 내보낸다.
- DecisionLog: 직하층 확인 여부와 시각, 추정과 실제가 달랐던 세대.

[4. 요구조자]
- 요구조자 배치는 집기 세트의 숨는 장소 가중치(장롯·이불·창가·화장실·베란다, SOP 202 4.1~4.2)를 따른다.

테스트: 같은 seed 는 같은 맵, 다른 seed 는 세대 변형·가구가 달라짐, 수직 연결부 위치는 모든 층에서 같음,
도면에는 변형·가구가 안 보임, 직하층 확인 후 위 세대가 점선 추정 구조로 표시되고 실제와 다르면 진입 후 덮어써짐,
짐 많은 세대가 일반 세대보다 가연물량이 크고 검색이 느림, 저사양 기준 15층 동 로드 시간 측정.
계획 먼저 보여주고 승인 후 구현.
