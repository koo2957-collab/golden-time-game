# P4-4. 지휘소·후착대 임무 받기 (기존 프로젝트 수정용)

> 사람용 메모(실행 전에 사람이 할 일):
> 현재 후착대가 자기 차 앞에만 서 있는 문제를 고칩니다. P10-2(명령 카드) 다음에 하면 좋습니다. 임무 부여 부담을 줄이는 기능(임무 예약·단위지휘관·대기열 화면)은 넣지 않았습니다.

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

docs/design.md 9-1-1, 9-1, 6-1(차량·작업) 을 읽어라.
현재 문제: 후착대원이 자기 차량 앞에만 있고, 지휘관을 움직일 이유가 360° 확인 외에는 거의 없다.
먼저 지휘관·후착대 도착·임무 부여 코드를 찾아 CLAUDE.md 비교 표로 보고하고 계획을 승인받아라.
임무 부여 방식 자체(명령 카드·원형 메뉴)는 이번에 바꾸지 마라.

[1. 지휘 방식 상태(CommandMode)]
- MOBILE(이동지휘, 시작값) / FIXED(고정지휘). 지휘관은 MOBILE 일 때만 직접 이동.
- 지휘관 명령 카드에 '지휘권 선언·지휘소 지정' 추가: 지도에서 위치를 찍으면 무전 선언(지휘관 신분·지휘 위치·전략, radio_lines.json) 후 FIXED.
- FIXED 에서 지휘소 반경(params) 밖으로 나가면 MOBILE 로 전환: 전술상황판 KnowledgeBoard 갱신 지연, 동시 무전 일부 누락(params).
- 지휘소 위치 평가(SOP 104 1.3): 건물 관찰 가능(시야 내 화재 건물 비율), 낙하물 위험반경(발화층 높이의 1/2) 밖, 차량 동선·배치 슬롯과 겹치지 않음.
  나쁘면 낙하물 경고 카드(data/cards) 와 DecisionLog 감점.
- 지휘대 도착(지휘권 이양) 후 기본 FIXED, 지휘소를 지휘차 옆으로 옮길 수 있음.

[2. 후착대 도착과 임무 받기]
- 도착 시 무전 도착 보고(출동대명·인원·위치). 운전원의 기존 자동 동작(소화전 점령·급수 등)은 그대로 둔다.
- 지휘소 미지정: 차량 옆에서 장비 준비 후 대기, 일정 간격으로 무전 "임무 주십시오"(무전 대기열에 부담).
- 지휘소 지정: 지휘소로 걸어와 줄을 선다(대기 자리, 겹치지 않게). 직전대기 장소가 지정되면 그곳으로.
- 줄 선 대는 기존 방식대로 선택해 임무를 준다. 기다린 시간은 DecisionLog 에 기록.
- FIXED 상태에서 지휘관이 떠나면 임무 없는 대원은 지휘관을 따라 모인다.

[3. 안전구역·통제선]
- 지휘관이 걸어가지 않고 구역 지정으로 찍으면 가까운 임무 없는 대원이 가서 설치(작업 시간 params).

테스트: 지휘소 지정 전 후착대는 차량 옆 대기, 지정 후 지휘소로 이동·줄서기,
지휘관이 지휘소를 떠나면 MOBILE 전환·상황판 갱신 지연, 낙하물 반경 안 지휘소는 경고,
디브리핑에 대기 총시간 기록.
계획 먼저 보여주고 승인 후 구현.
