# P7. 질문 카드 엔진 (단계 4)

[먼저 읽을 것] 이 프롬프트는 이미 만들어진 프로그램을 고치기 위한 것이다. 프로그램은 기획안을 고치기 전 버전으로 만들어져 있다.
CLAUDE.md 의 '기획안과 현재 구현이 다를 때' 절차를 따라라: 관련 코드를 먼저 읽고, 기획안·현재 구현·상용 게임 방식을 비교한 표와 추천을 보여 준 뒤,
내가 고르면 구현해라. 이미 구현돼 있고 기획안과 같은 부분은 다시 만들지 말고 확인만 해라.

docs/design.md 3장 전체와 7장을 읽어라. 게임은 질문 중에도 절대 멈추지 않는다.
- CardEngine: 트리거(게임 상태 조건)를 감시하다가 카드를 만든다. 트리거는 JSON 의 조건 식(예: team_at_door & door.room.smoke>0.3)으로 쓴다.
- 변형(variants): 상황에 따라 문구·정답 등급이 바뀐다(예: 백드래프트 징후 유무). 선택지 순서는 매번 섞는다.
- CardQueue: 최대 3장, 긴급도(일반 20초·중요 12초·긴급 8초, params.json), 긴급은 앞으로 끼어듦, 만장 시 무전 로그 대기.
  훈련 난이도에서는 제한시간 2배.
- 미응답: 대원은 '지시대기'로 멈춘다(안전한 기본값을 주지 않는다). 시간은 계속 흐른다.
- 선택 시 effect 키를 행동으로 실행한다. 결과는 시뮬이 만든다(카드가 직접 폭발을 일으키지 않는다).
- 선제지시: skip_if_preordered 명령이 이미 내려져 있으면 카드를 띄우지 않고 '선제지시'로 기록.
- 모든 카드·선택·응답시간·이후 결과 이벤트를 DecisionLog 에 남긴다. 결과는 '원인 카드 id' 로 연결한다(디브리핑용).
- UI: 화면 가운데에 반투명하게 뜨는 카드(한 번에 한 장, 답하면 사라지고 '질문 → 내 답'이 상황판 무전 기록에 등록). 질문한 대원의 큰 일러스트(역할 5종 x 상태 3종, 초기에는 실루엣), 둘레 링으로 남은 시간,
  말풍선 질문, 아래 큰 선택 버튼 2~4개(번호 표시, 클릭 또는 1~4). 다른 대기 카드는 카드 모서리에 '+N' 으로 표시하고, 답하면 다음 카드가 뜬다. 카드는 화면 1/4 이하, 반투명.
  일러스트 클릭 또는 Space 로 그 대원 위치로 이동. 지도는 뒤에서 계속 움직인다.
- 게임 중에는 정답/오답을 표시하지 않는다.
테스트: 카드 30장 로드, 트리거 조건별 발동, 대기열 우선순위, 미응답 시 지시대기, 선제지시 시 미발동.
계획 먼저, 승인 후 구현.
