# Fire Commander 기획서

- 버전: v2.1 (2026-11-07 확정)
- 대상: 현직 소방공무원 (내부 교육용, 내부 배포)
- 플랫폼: Windows PC / Godot 4.7 / GDScript
- 근거 자료: 중앙소방학교 「소방전술 I」 화재1·화재2 (SOP 조항 번호는 이 교재 기준)

---

## 1. 설계 원칙

> **SOP를 지키면 시뮬레이션 안에서 실제로 더 좋은 결과가 나오고, 평가는 그 인과관계를 사후에 보여준다.**

- 플레이어 = **현장지휘관**. 지휘권 선언, 상황평가, 전략 선언, 진입 명령, 자원 배치, 디브리핑을 실제 절차대로 수행한다.
- 교육: SOP 체크리스트를 클릭하는 게임이 아니다. 절차를 무시하면 시뮬레이션 결과로 대가를 치른다.
- 재미: 긴장감(골든타임), 트레이드오프 판단, 불완전 정보, 극적 순간, 재도전 동기.
- 사실성: 현직자 대상이므로 파워업, 장비 해금 같은 비현실적 장치는 넣지 않는다.

| 전략 선언 | 공격·방어·병행. 대원 기본 행동 변경, 화재 단계에 맞는지 평가 | SOP 106-2 |
| 진입 금지 명령권 | 무전 진입 명령 전에는 내부 진입 불가 | SOP 102-5 |
| 방면·단위지휘관 | A~D면 명칭, 단위지휘관 지정. 직접 관리하는 출동대가 많으면 명령 지연(통솔범위) | SOP 105-2 |
| 무전 | 채널 용량이 자원. 우선순위: 대원안전 → 구조대상자 → 주요요소 → 전술 | SOP 107 |
| 자원 순차 도착 | 후착대는 대기 1단계, 지휘관이 투입 시점 결정. 대규모 시 자원대기소 | SOP 103-2 |
| 현장안전담당·RIT | 안전담당 지정 시 위험 징후 사전 경고. RIT 대기 vs 투입 트레이드오프 | SOP 108, 102-4.3 |
| 긴급탈출 | 3회 무응답 시 긴급탈출 상황. 무선 침묵, RIT 투입, 공기 공급 | SOP 109, 204 |
| 지휘권 이양 | 지휘대장 도착 시 진행 상황 보고 후 이양 | SOP 112 |

## 4. 시간 시스템

전 구간 고정 배속은 **채택하지 않는다**.
판단 게임이 손 빠르기 게임으로 바뀌고, 전조 신호를 관찰할 시간이 사라지기 때문이다.

- **단일 게임 시계**: 화재·대원·차량이 같은 시계로 진행. 화면에는 실제 경과 시간을 표시해 시간 비율 감각을 유지한다.
- **판단 없는 구간 생략·요약**: 출동 이동, 복귀.
- **플레이어 배속**: 1·2·4배 (`F1`/`F2`/`F3` 키. 숫자 키는 RTS 관례대로 부대 지정에 쓴다).
- **자동 감속**: 위험 징후, 긴급탈출, 요구조자 발견, 무전 보고 수신 시 1배속으로 자동 복귀.
- **모드별 차이**: 교육 모드는 일시정지 가능(`Space`), 실전 모드는 일시정지 불가.
- 목표 플레이 시간: 주택화재 미션 15~20분.

## 5. 화재 시뮬레이션

### 5-1. 구조
- **구획 모델** (방 단위, 핵심 판정): 상부 고온층 / 하부 저온층 2층 모델. 온도, 연기층 높이, 산소, CO 농도, 개구부 상태. 위험 현상은 여기서 판정한다.
- **셀 그리드** (0.5m): 가연물 분포, 화염 확산 표현, 방수 대상 지점, 이동 경로.
- 다층 건물은 층별 탭으로 전환한다. 연기와 열은 계단·샤프트로 상승한다.
- 고정 틱 + 시드 기반 결정론으로 리플레이와 "특정 시점부터 다시 하기"를 지원한다.

### 5-2. 교재 근거 수치 (`data/fire/`에 저장)

| 항목 | 값 | 출처 |
|---|---|---|
| 플래시오버 온도 | 483~649℃ (CO 발화온도 609℃) | 화재1 제2장 제5절 |
| 플래시오버 시점 | 목조 5~6분, 내화조 20~30분 | 〃 |
| 최성기 온도 | 800~900℃ (목조) | 〃 |
| 플래시오버 복사열 | 20kW/㎡ 초과 | 〃 |
| 플래시오버 시 방화복 착용 생존 | 2초 이내, 탈출 속도 0.75m/s → 1.5m 이상 진입 금지 | 〃 |
| 피부 손상 온도 | 137~160℃ | 〃 |
| CO 폭발범위 | 12~74% | 〃 (백드래프트) |
| FGI 대피 기준 | 열화상 350℃ 이상 | SOP 210-10.5.4 |
| 낙하물 위험반경 | 발화층 높이의 1/2 ~ 건물 높이 | SOP 205-1.3, 213-2.8.1 |
| 붕괴 우려 철수 거리 | 건물 높이의 1.5배 이상 | SOP 205-3.5 |

교재에 없는 값(요구조자 생존 시간, 공기호흡기 사용 시간, 방수량 등)은 `"source": "추정"`으로 표시하고 현장 검수를 받는다.

### 5-3. 위험 현상과 전조 신호

| 현상 | 전조 신호 | 올바른 대응 |
|---|---|---|
| 롤오버 → 플래시오버 | 복도 천장의 굽이치는 화염, 고온 농연 하강 | 문 닫기, 냉각 주수, 1.5m 이상 진입 금지 |
| 백드래프트 | 닫힌 문 주위 검은 연기, 연기 역류, 창의 타르, 휘파람 소리 | 하부 개방 금지, 상부 수직배연 후 진입 |
| 화재가스발화(FGI) | 높은 천장·빈 공간의 연기 축적 | 점화원 관리, 3D 주수, 배연 |
| 붕괴 | 균열음, 박리, 장시간 연소 + 대량 방수 | 철수 거리 확보, 불필요한 직사주수 금지 |

### 5-4. 진압·구조
- 방수: 직사·분무·3D 주수. "천장 → 벽 → 수용물 → 바닥", "미연소 → 연소 방향" (SOP 206). 과다 방수 시 수손·붕괴 위험 (SOP 205).
- 물 공급: 탱크, 소화전 점령, 물탱크차 급수, 순환보수 (SOP 200-3.1). 수관은 차량에서 방수 위치 방향 (SOP 208).
- 대원: 공기 잔압, 열 스트레스, 피로, 2인 1조 (SOP 201-3.7), 휴식처 회복 (SOP 201-3.5).
- 요구조자: 인명검색 중점지역 확률 배치 (SOP 202-4), 노출에 따른 생존 시간, 구조 우선순위 (SOP 203-1.4).
- 검색: 우선·교차·정밀 탐색 (SOP 202-5), 검색 완료 표시와 무전 전파 (SOP 212-2.1).

## 6. 평가 시스템

평가 축 (SOP 106 전술 우선순위 순서 = 가중치 순서):

1. **대원 안전**: 2인 1조, 공기 고갈, 무명령 진입, 위험반경, 안전담당, 부상
2. **인명구조**: 구조 인원, 소요 시간, 우선순위 준수
3. **재산 보호**: 소실 면적, 인접 연소 확대, 수손
4. **화재 안정화**: 초진·완진 시간, 재발화
5. **지휘 절차**: 지휘권 선언 시점, 상황보고 정확도, 전략 적합성, 무전, 자원 운용

- 중대한 안전 SOP 위반 시 종합 등급 상한 적용 (SOP 108-1.2).
- 모든 평가 항목에 SOP 조항 ID를 연결한다. 디브리핑에서 조항 원문을 보여 준다.
- 절차를 형식적으로만 수행하고 결과가 나쁘면 고득점이 불가능하게 한다.

디브리핑 (SOP 113-2):
1. 무엇을 계획했나? 2. 실제로 무슨 일이? (타임라인 리플레이, 숨겨진 정보 공개)
3. 왜 일어났나? (판단 → 결과 → 조항) 4. 다음에는? (약점 교정, 강점 유지)
비난 없는 검토 원칙 (SOP 113-3): 잘한 판단도 반드시 표시한다.

결과는 `user://reports/`에 저장한다.

## 7. 게임성

| 요소 | 구현 |
|---|---|
| 긴장감 | 요구조자 남은 시간은 숫자 대신 신호로 전달. 대원별 공기 잔압 |
| 트레이드오프 | RIT 대기 vs 투입, 즉시 진입 vs 배연 대기, 부족한 물의 배분 |
| 정보 퍼즐 | 부정확한 신고, 진술 신뢰도, 단서 추론 |
| 극적 순간 | 특수현상 연출(흔들림, 폭음, 무전 혼선), 긴급탈출 무전 재현 |
| 대원 개성 | 이름·숙련도·특성. 신임 대원은 숙련자와 조편성 (SOP 108-3.2). 캠페인에서 피로·부상 누적 |
| 성장 | 가상 관할 소방서 캠페인. 계급에 따라 지휘 범위 확대: 선착대장 → 지휘팀장 → 대응단장 → 통제단장. 해금 대상은 장비가 아니라 권한과 시나리오 |
| 재도전 | 시나리오 무작위 변수, 등급, 도전과제 |
| 다시 하기 | 디브리핑에서 특정 시점으로 돌아가 재플레이 |
| 직원 간 경쟁 | "이번 주 훈련 시나리오": 같은 시드로 소방서 전원 플레이, 결과 파일로 순위 비교 |

## 8. 시나리오 시스템

- **① 같은 유형의 변형**: 데이터(JSON)만 추가한다.
- **② 새 화재 유형**: 유형 모듈(코드)을 한 번 개발한 뒤 ①처럼 확장한다. 예: 풀 파이어, BLEVE.

`scenario.json` 구성:
`meta`(ID, 제목, 대응 SOP, 학습 목표, 난이도, 플레이어 역할) / `dispatch` / `map` / `building` / `fire` / `victims` / `resources` / `variation` / `events` / `sop_rules` / `scoring`

- SOP 규칙 라이브러리 (`data/sop/`)의 규칙 유형: 시간 제한, 순서, 금지, 상태 유지. 시나리오는 규칙 ID만 참조한다.
- 불러오는 위치: `res://data/scenarios/` (기본), `user://scenarios/` (추가).
- 불러올 때 검증하고 한글 오류 메시지를 보여 준다.
- 후기 단계: 게임 내 시나리오 에디터.

## 9. 기술 구조

```
[입력/UI] → 명령 객체 → [무전·지휘 계층] → [시뮬레이션 코어(고정 틱)] → 이벤트 로그 → [SOP 판정·평가]
                         (통솔범위·무전 지연)            ↓
                                                  [화면: 도면 맵, 열화상, 효과]
```

## 10. 아트 스타일

두 화면을 함께 쓴다 (Tab 전환, 시안 단계 — 사용자 비교 후 확정).

- **입체 (기본 플레이, 아이소메트릭 2:1)**: 뒤쪽 외벽만 천장 높이, 나머지 벽은 낮게 잘라 실내를 보여 준다. 연기층은 천장에서 내려온 높이에 반투명 평면으로 그려 "연기층 하강"을 높이로 보여 준다 (SOP 201 낮은 자세, 플래시오버 전조 판단).
- **상황판 (평면도)**: 도면 맵, 단순한 벡터 아이콘(대원 = 원형 + 분대 색·번호, 차량 = 차종 심볼). 전체 상황 파악과 지휘 판단용.
- 두 화면 모두 열화상 전환(T)을 지원한다. 초기에는 코드로 그린 도형으로 개발한다.
- 시뮬레이션은 화면과 분리되어 있어 두 화면이 같은 상태를 읽는다 (`ViewProjection`으로 좌표 변환만 다름).
