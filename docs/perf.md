# 성능 기록 (P14)

측정 PC: i5-9500 · UHD Graphics 630 (기획안 최저 사양 8세대 i5·UHD 620과 비슷한 급), Godot 4.7.2 Compatibility.

## 1. 시뮬레이션 1틱 비용 — 15층 아파트 (sop213_3, 시작 5분 뒤, 300틱 평균)

| 단계 | 1틱 평균 | 화재(칸) | 시야 | 그 밖 |
|---|---|---|---|---|
| R17까지 | **31.8ms** | 22.9ms | 6.9ms | 2.0ms |
| 화재 칸: 타는 칸·열 받는 구획만 계산 | 12.1ms | 3.3ms | 6.9ms | 1.9ms |
| 시야: 창 들여다보기 5회에 1번, 보인 칸만 지우고 기록·메우기 | 9.3ms | 3.2ms | 4.2ms | 1.9ms |
| 시야: 3층 이상 창은 창 바로 안쪽(2m)만 | **8.1ms** | 3.3ms | 2.6ms | 2.2ms |

- 1초 10틱이므로 1배속에서 시뮬레이션이 CPU를 약 8%, 2배속(기획안 5-8 현장 시계)에서 약 16% 쓴다. R17 때는 1배속에서도 32%를 써서 화면이 끊겼다.
- 위 수치는 다른 자동 점검을 함께 돌리던 중에 쟀다 (혼자 돌리면 조금 더 낮다).

### 바꾼 것

| 곳 | 전 | 후 | 정확도 |
|---|---|---|---|
| FuelGrid.step 1단계 | 모든 가연물 칸(15층 약 2만 칸)을 매 틱 확인 | 지난 틱에 타던 칸 + 새로 붙은 칸만 | 같음 |
| FuelGrid.step 2단계(가열·착화) | 모든 타지 않은 칸 | 타는 칸이 있거나, 고온층 복사 0.5kW/㎡ 이상이거나, 문 너머·벽 너머 열을 받는 구획의 칸만. 쉬던 구획은 다시 계산할 때 쉬는 동안 식은 만큼 한 번에 적용 | 빠지는 칸이 받는 열은 가장 쉬운 재질 착화 열의 10분의 1 미만 → 착화를 놓치지 않음 |
| FuelGrid.step 3단계(구획 합계) | 모든 칸을 다시 합산 | 탄 만큼 빼는 누적 | 같음 |
| Perception | 전체 배열(4만 칸)을 매번 지우고 메우고 기록 | 보인 칸 목록만 | 같음 |
| Perception 창 들여다보기 | 매번 135개 창 × 20줄 | 5회(약 1.5초)에 1번, 그 사이는 지난번 칸 재사용 (불·연기 상태는 매번 기록) | 창 시야가 1.5초 늦게 갱신 |
| Perception 높은 층 창 | 1·2층과 같이 방 안 6m까지 | 땅에서 3층 이상은 창 바로 안쪽 2m (밖에서 높은 층 방 안 구조는 보이지 않음) | 현실에 더 가까움 |

수치: `data/fire/fire_params.json` cell_active_min_kw_m2, `data/units/firefighter.json` window_view_every·window_view_low_floors·window_view_high_range_m (모두 게임 설정값).

## 2. 저사양 모드 (기획안 9-5)

화면 설정 → '저사양 모드' 켜기: 30프레임 고정 + 단면 보기에서 함께 쌓는 아래층을 1개로. user://display.json `low_spec`.

## 3. 재는 법

```
GODOT --headless --path . -s res://tests/benchmark.gd    # 시나리오별 틱 비용 (성능_측정.bat)
GODOT --path . -s res://tests/ui_cutaway.gd               # 15층 화면 프레임 측정
```
F12: 게임 안 성능 표시 (fps · 프레임 ms · 시뮬레이션 ms · 그리기 호출 · 메모리).

## 4. 남은 것

- 화면 그리기: 15층 외부 보기·단면은 R17 측정에서 그리기만 45~58fps. 고정 도형(벽·가구)을 층마다 한 번 만든 삼각형 묶음으로 그리면 더 빨라진다 (그래픽 교체 P15 때 함께).
- 25층·초고층은 다시 재야 한다 (benchmark.gd).
