# 기획안 대비 현재 게임 차이 분석

- 비교 대상: 「소방 지휘관 RTS 훈련게임 개발 기획안」(2026-11-08, 이하 **기획안**) ↔ 현재 Fire Commander (M0~M9d, P1 완료, 이하 **현재**)
- 작성: 2026-11-08

## 1. 한 줄 판단

**엔진(시뮬레이션·지휘 절차·평가)은 기획안보다 앞서 있고, 플레이 방식(질문 카드·실시간·임무형 내부 지휘·화면 배치)과 스테이지 구성은 기획안에 못 미친다.**
기획안은 "아파트 일부만 있는 Godot 프로젝트"를 전제로 P0부터 다시 쌓도록 쓰였다. 현재 코드(GDScript 약 1.7만 줄, 단위 테스트 156개)는 그 전제보다 훨씬 많이 만들어져 있으므로, **P0~P14를 그대로 돌리면 이미 동작하는 기능을 다시 만들거나 부수게 된다.** 프롬프트는 "만들 목록"이 아니라 **차이를 메우는 점검표**로 쓴다.

## 3. 서로 부딪히는 설계

| 항목 | 기획안 | 현재 | 영향 |
|---|---|---|---|
| 시간 | **항상 실시간, 1배속 고정**, 질문 중에도 멈추지 않음 | 1·2·4배속, 교육 모드 일시정지, 창이 열리면 시간 정지 | 질문 카드 제한시간이 의미를 가지려면 실시간이어야 함 |
| 내부 조작 | 내부 조는 직접 이동 불가, 임무·무전으로만 | 내부도 우클릭 이동 가능 | 기획안 9-1의 핵심 원칙 |
| 판정 방식 | 카드 선택지 등급(최선·허용·오답·치명) + 시뮬 결과 | 상태 기반 SOP 판정 규칙 40개 | 둘 다 쓰면 됨: 규칙은 그대로, 카드 점수를 SOP 준수 축에 더함 |
| 플레이 시간 | 1회 15~25분 (교육 1교시) | 제한 시간 40~60분 (배속 전제) | 1배속 고정이면 제한 시간을 25분 안팎으로 줄여야 함 |
| 지휘권 이양 | 이양 후 **지휘대장으로 계속 플레이** | 미구현 (next_plan.md는 "이양 시 종료" 권장) | 기획안을 따르면 이양은 종료가 아니라 역할 전환 |
| 종료 | 완진 → 잔불정리 → 복귀 보고 = 성공, 대원 사망 시에도 계속 | 활동 종료 선언·제한 시간뿐 | next_plan.md M10 설계와 같은 방향 (그대로 반영) |
| 그래픽 | 64×32 타일, 8방향 스프라이트 | 코드로 그린 도형 | 기획안도 "초기에는 단색 도형" → 나중에 한 번에 (G1) |

## 4. 수치 차이

| 항목 | 기획안 | 현재 | 제안 |
|---|---|---|---|
| CO 사망 | 교재 표 4-11 사망시간으로 "노출시간/사망시간" 누적 (1,600ppm 120분 … 12,800ppm 2분) | 공학식 FED (ppm^1.036/35000, 1.0 의식 잃음, 3.0 사망) | 교재 표로 바꾸고 기존 공학식은 비교용 테스트로 남김 (교재 근거가 우선) |

| 평가 배점 | 안전 30·인명 30·재산 10·진압 10·SOP 준수 20 | 축 가중치(rules.json) | 기획안 배점으로 바꾸고 "지휘 절차" 축을 "SOP 준수"로 넓힘 |

## 5. 개선 방향 (권장)

1. **엔진은 살리고, 플레이어가 만지는 층을 기획안대로 바꾼다.** 화재·대원·물·평가 코드는 그대로 두고, 그 위에 질문 카드·실시간 규칙·임무형 내부 지휘·새 화면 배치를 얹는다.
2. **기존 "멈춰서 지시 바람" 지점을 질문 카드로 바꾼다.** 잠긴 문, 백드래프트 징후 문, 발견한 요구조자처럼 지금 조가 멈추는 곳이 이미 판단요청 자리다. 여기에 선택지·등급·제한시간을 붙이는 것이 가장 빠른 길이다.
3. **종료 체계(M10)를 기획안 8장 종료 조건으로 맞춰 먼저 끝낸다.** 판이 끝나야 카드 점수·디브리핑을 시험할 수 있다.
4. **스테이지는 기획안 4-1 순서(아파트 2-1 버티컬 슬라이스 우선)**를 따르되, 이미 있는 5층 아파트를 15층으로 키우는 데서 시작한다.
