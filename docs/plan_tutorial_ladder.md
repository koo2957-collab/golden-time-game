# 기능 사다리 계획 — 가장 쉬운 튜토리얼부터 하나씩 완성하기

2026-11-11. 사용자 요청: "가장 초보적인 튜토리얼부터 하나씩 기능을 완성하여 다음 기능들을 확장하는 방식으로".

## 1. 왜 바꾸는가 (지금 상태 진단)

- 지금까지는 기획안 절마다 프롬프트(P0~P15)로 **기능을 넓게 먼저** 만들었다. 결과:
  - 스크립트 약 3만 줄, 자동 테스트 351개가 모두 통과한다.
  - 그런데 **사람이 처음부터 끝까지 해 보면 어색하다.**
- 자동 테스트는 "명령을 넣으면 시뮬레이션이 맞게 움직이는가"를 본다. "처음 하는 소방관이 화면만 보고 할 수 있는가"는 보지 않는다. 어색함은 이 빈틈에서 생긴다.
- 기능이 한꺼번에 켜져 있어서, 하나가 이상하면 원인을 알기 어렵다.
  - 예: 무전 지연 · 진입 허가 · 질문 카드 · 정보 안개 · 연기 · 통솔범위가 동시에 작동한다.
- 튜토리얼(data/tutorial/basics.json)도 예전 조작으로 쓰여 있다.
  - 원형 메뉴, W → 방 클릭 같은 설명이 남아 있다.
  - 오늘 바꾼 조작(노란 진입구 · 층 · 방, 즉시 지시)과 맞지 않는다.

## 2. 원칙

1. **사다리 한 칸 = 레슨 하나 = 작은 시나리오 하나.**
   - 그 칸에서 새로 배우는 기능은 1~2개뿐이다.
   - 아직 배우지 않은 기능은 시나리오의 **기능 스위치**로 꺼 둔다.
2. **완료 기준은 사람 기준이다.**
   - 처음 하는 사람이 화면 안내만 보고 5분 안에 끝낼 수 있어야 한다.
   - 사용자가 직접 해 보고 "됐다"고 해야 다음 칸으로 간다.
3. **다음 칸은 앞 칸 위에 쌓는다.**
   - 앞 칸의 기능을 고치면 앞 칸 레슨을 다시 확인한다(자동 + 사용자).
4. **지금 코드는 버리지 않는다.**
   - 다시 만드는 것이 아니라 칸마다 검증하고 다듬는다.
   - 아직 검증하지 않은 기능은 레슨에서 꺼 두기만 한다. 본 스테이지에서는 그대로 켜져 있다.
5. **작업 방식(2026-11-11 결정)은 그대로다.**
   - 한 번에 작업 하나 → 관련 테스트만 → 사용자 확인 → 다음 작업.
   - 전체 테스트는 커밋 뒤 test_bg.ps1로 뒤에서 돌린다.

## 3. 칸마다 하는 일 (반복)

1. **레슨 설계:** 배울 것, 쓰는 기능, 꺼 둘 기능, 화면 안내 문장, 완료 조건을 정한다.
2. **만들기:** 레슨 시나리오 JSON + 안내 단계(data/tutorial/) + 필요한 고침.
3. **자동 확인**
   - 관련 테스트를 돌린다.
   - **봇 플레이**: 스크립트가 안내대로 끝까지 플레이하며 단계마다 화면을 찍는다.
   - 찍은 화면은 내가 먼저 보고, 어색한 곳을 고친다.
4. **사용자 플레이(10분):** 이상한 점을 말해 주면 그 칸 안에서 고친다.
5. **"됐다" → 다음 칸.** 칸마다 진행 기록(docs/progress.md)과 레슨 안내(docs/test_guides/)를 남긴다.

## 4. 사다리 (레슨 순서)

| 칸 | 레슨 | 새로 배우는 것 | 켜는 기능 | 끄는 기능 | 완료 조건 |
|---|---|---|---|---|---|
| 0 | 준비 | — | **기능 스위치 만들기**, 이상한 점 목록 정리, 튜토리얼 틀 정리 | — | 레슨 시나리오에서 기능을 하나씩 끄고 켤 수 있음 |
| 1 | 화면 보기 | 외부 보기·층 막대·확대·이동·일시정지 | 건물·카메라 | 불·연기·카드·무전 지연·차량 도착 연출 | 원하는 층 단면을 찾아 보고 돌아온다 |
| 2 | 지휘관 | 우클릭 이동, 둘러보기, 지휘소 | + 지휘관 | 대원 명령 | 건물 네 면을 돌아보고 지휘소에 선다 |
| 3 | 대원 진입 | 조 선택 → 노란 진입구 → 진입 허가 → 층 → 방 | + 대원 이동·진입 허가 | 불·연기·질문 카드 | 2조를 서로 다른 문으로 3층 방까지 보낸다 |
| 4 | 인명검색 | 검색 · 발견 · 업고 나오기 · 집결지 | + 요구조자(불 없음) | 불·연기 | 요구조자 1명을 집결지까지 |
| 5 | 수관·방수 | 펌프차 → 수관 연장 → 방수 → 물 부족 | + 작은 불(방 하나), 물 | 연기 확산·카드 | 불을 끄고 물탱크를 확인한다 |
| 6 | 연기·시야 | 연기층, 정보 안개, 열화상 | + 연기·시야 | 카드 | 연기 속 요구조자를 열화상으로 찾는다 |
| 7 | 질문 카드 | 문 개방·주수 방법 카드, 선제지시 | + 카드(2~3장) | — | 카드 답에 따라 결과가 달라지는 것을 본다 |
| 8 | 무전·상황판 | 보고·전술상황판(보고된 것만) | + 무전 보고·상황판 | — | 상황판으로 요구조자 위치를 확인한다 |
| 9 | 안전 | 공기·RIT·인원점검·철수 | + 공기·RIT·PAR | — | 공기 경보 뒤 교대·인원점검 |
| 10 | 지휘 흐름 | 지휘권 선언·최초 상황보고·전략 | + 선언·보고 | — | 8항목 보고를 맞게 보낸다 |
| 11 | 통합 | 단독주택 화재 한 판 (스테이지 1-1) | 전부 | — | 디브리핑까지 |

## 5. 0칸(준비)에서 할 일

1. **기능 스위치:** 시나리오 JSON에 `features` 를 둔다.
   - 예: `{"fire": false, "smoke": false, "cards": false, "fog": false, "arrival_drive": false, "entry_permission": true}`
   - 이미 있는 스위치(entry_order_required, realism 등)를 한곳으로 모은다.
   - 꺼진 기능은 화면에서도 숨긴다(버튼·패널).
2. **이상한 점 목록 (docs/odd_list.md):**
   - 사용자가 느낀 점 + 봇 플레이 화면에서 내가 찾은 점.
   - 칸 번호를 붙여, 그 칸에서 고친다.
3. **튜토리얼 틀:** 레슨 목록 화면(시작 메뉴 '훈련')과 레슨마다 안내 단계 파일.
   - 지금의 basics.json은 11칸(통합)으로 옮긴다.
4. **봇 플레이 도구:** 레슨 안내 단계를 따라 자동으로 플레이하며 단계마다 화면을 찍는 스크립트.
   - 기존 _shot_*.gd를 묶는다.

## 6. 예상 기간

- 칸 하나에 작업 1~3개.
- 사용자 확인을 포함하면 칸당 반나절~하루.
- 0~11칸 전체는 2~3주.
