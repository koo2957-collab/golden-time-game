# 튜토리얼 완성 계획 v2 (G 단계)

작성 2026-11-13 (v1을 같은 날 사용자 의견으로 다시 씀). 아직 확정 전 — 9장의 질문에 답을 받은 뒤 확정한다.

## 0. 방향 (사용자 결정 2026-11-13)

1. **튜토리얼 하나를 완벽히 완성한 뒤 다음 스테이지로 간다.** 튜토리얼에서 만든 기능을 다음 스테이지가 그대로 다시 쓴다.
2. **먼저 게임성, 그다음 교육 내용.** 목표·실패·조작이 재미있게 돌아가는 게임을 먼저 만들고, 그 위에 SOP 안내·디브리핑을 올린다.
3. **SOP 내용은 고치거나 각색하지 않는다.** 시뮬레이터 역할도 해야 한다.
4. **대원 기본기능을 먼저 만든다:** 화재진압대원 → 구조대원 → 구급대원. NPC(주민·관계인) 행동은 그 시나리오에 필요한 것만 만들고 나머지는 그 스테이지에서 만든다.
5. **새로 만들지 않고 지금 프로그램을 고친다.**
6. **일하는 방식:** 단계마다 현재 상태 보고 → 질문·비교표로 방식 확정 → 구현 → 관련 테스트 → 커밋·푸시 → 사용자가 직접 해 보고 확인 → 다음 단계.

## 1. 지켜야 할 원칙 네 가지

| 원칙 | 뜻 | 지키는 방법 |
| --- | --- | --- |
| **SOP 원문 그대로** | 게임이 SOP처럼 보이는 문장을 지어내지 않는다 | 카드·안내·디브리핑의 근거 문장은 2025 SOP 조항을 그대로 옮기고 조항 번호를 붙인다. SOP에 없는 것(게임 수치·연출)은 '게임 설정'으로 따로 표시한다. SOP에 없는 행동은 감점하지 않는다 |
| **사건은 물리에서** | 위기는 대본이 아니라 시뮬레이션이 만든다 | 긴장은 초기 조건(가스 밸브 열림, 닫힌 문, 바람, 잠긴 현관)으로 만든다. "몇 단계가 끝나면 터진다" 같은 대본은 쓰지 않는다. 사망을 부상으로 낮추는 보정도 하지 않는다 (v1 제안 철회) |
| **원인 → 본 사람 → 보고** | 일어나지 않은 일은 보고되지 않고, 아무도 못 본 일도 보고되지 않는다 | 모든 보고·징후·카드는 ① 시뮬레이션에 실제 상태가 있고 ② 이름 있는 대원(또는 지휘관)이 보거나 느낄 위치에 있을 때만 나온다 |
| **목표가 있는 게임** | 무엇을 하면 이기고 무엇이면 지는지 시작할 때 안다 | 작전 목표·실패 조건을 화면에 보여 주고, 실패하면 사유와 함께 다시 하게 한다 |

## 2. 지금 상태 (2026-11-13 코드 확인)

| 지적하신 점 | 코드에서 확인한 사실 | 판단 |
| --- | --- | --- |
| 출동 중에 할 일을 도착해서 다 한다 | 출동 단계는 창 하나다 (지령 문장이 90초 동안 차례로 나오고 차량 배치·장비·임무 미리 정하기를 고른 뒤 '현장 도착'). 그런데 예비 소방용수(200-2.2)·관계자 조치 요청·공기호흡기 점검 등 **'도착' 질문 카드 8장이 도착 뒤에 뜬다** | 지적이 맞다. 출동 중 결정이 도착 뒤로 밀려 있다 |
| 조작이 복잡하다 | 명령 묶음이 5가지(조·구급·차량·지휘관·문)에 지휘관 명령은 2단 메뉴다. 예: RIT 지정 = 선택 해제 → E 지원 요청 → W 조직·안전 임무. 지휘권 선언 = Q 전략 변경 → Q 선언·전략. 여기에 방 클릭 임무 창, 문 앞 휠, 질문 카드가 따로 있다 | 지적이 맞다. 같은 종류의 일을 하는 길이 여러 개다 |
| 대원이 잘 움직이지 않는다 | 대원이 멈추고 "지시 바람"을 보내는 경우가 10가지가 넘고(문 닫힘·잠김·징후·방수 위치 없음·검색 시작 못 함 등), 카드에 답하지 않으면 멈춘 채로 있는다. 왜 멈췄는지는 무전 기록을 읽어야 안다 | 원인 후보는 있으나 **확정은 G1 점검에서** (실제로 돌려 봐야 안다) |
| 일어나지 않은 일·못 본 일이 보고된다 | 백드래프트 징후는 '보이거나 대원이 근처일 때만' 알리게 되어 있다. 그러나 **옆집 가열 보고는 본 대원이 없어도 "현장 대원" 이름으로 나온다** (`exposure_system.gd`). 문 단서 보고도 같은 방식이다. 카드 문구가 실제 상태와 무관하게 고정된 곳도 점검이 필요하다 | 지적이 맞다. 전체 보고 종류를 하나씩 점검해야 한다 |
| 화재 진압 목표가 없다 | 끝나는 경우는 넷: 작전 완료·조기 종료·전소(70% 이상 소실 또는 붕괴)·미완료. **전소가 아니면 불이 스스로 꺼질 때까지 기다려도 끝낼 수 있고, 대원·구조대상자 사망은 종료 조건이 아니다** (기획안 8-3 "대원이 사망해도 계속") | 지적이 맞다. 승패가 없다. 기획안 8-3을 바꾸는 결정이 필요하다 |

## 3. 맵을 3D로 만들 것인가 — 판단: 지금은 하지 않는다

| 항목 | 내용 |
| --- | --- |
| 지금 구조 | 맵 **데이터는 이미 3차원**이다 (층마다 0.5m 칸, 층 높이, 계단, 문·창 높이). 시뮬레이션은 화면을 모른다. 2D인 것은 **그리는 방법**뿐이다 |
| 3D로 바꾸면 얻는 것 | 자유 회전, 높은 건물·뒷면 보기, 가려짐이 자연스러움 |
| 드는 것 | 건물 그리기 코드 약 3,300줄과 어제까지 맞춘 층 표시 규칙을 다시 만든다. 대원·차량·집기 그림(Blender로 구운 2D)을 3D 모델로 다시 넣는다. 수 주 걸린다 |
| 위험 | 대상이 GPU 없는 사무실 PC다 (코드 규칙 1번이 3D 금지). 단순한 3D는 내장 그래픽에서도 돌 수 있지만 **대상 PC에서 재 보지 않았다** |
| 지금 문제를 푸는가 | **아니다.** 2장의 다섯 문제는 모두 시뮬레이션·지휘·조작의 문제이고 그리는 방법과 무관하다. 시나리오 구현(대원 기능·상호작용·목표)은 3D가 아니어도 그대로 된다 |

- **추천:** 튜토리얼을 지금 화면으로 완성한다. 시뮬레이션과 화면이 분리되어 있어서, 나중에 3D로 바꿔도 이번에 만드는 기능은 그대로 남는다.
- 튜토리얼이 끝나면 **"90° 회전(B안)이냐 3D냐"를 한 번에 정한다.** 둘 다 하면 B안 작업이 버려지기 때문이다. 그때 하루 이틀짜리 3D 시험판을 만들어 사무실 PC에서 속도를 재 보고 정한다.

## 4. 게임 뼈대: 목표·실패·완료 (안)

### 4.1 작전 목표 (시작할 때 화면에 보여 줌)

| 목표 | 달성 | 실패 (작전 실패) | 근거 |
| --- | --- | --- | --- |
| 인명구조 | 도착 때 살아 있던 구조대상자를 모두 살려서 구조·인계 | 도착 때 살아 있던 구조대상자 사망 → **인명구조 작전 실패** | SOP 106-1.1② 우선순위, 214-2.1 |

### 4.2 완료 조건

절차를 모두 마쳐야 '작전 완료'가 된다: 초진 보고 → 잔불정리·2차 검색 → 완진 선언 → 인원점검 → 활동 종료 선언. 중간에 끝내면 '조기 종료'(미완료)로 기록한다.

### 4.3 실패했을 때

화면: **작전 실패 — 사유 — 관련 SOP 조항 원문** + 단추 세 개 [직전 시점부터 다시] [처음부터 다시] [디브리핑 보기]. '이 시점부터 다시 하기' 기능은 이미 있다.

### 4.4 점수

실패가 아니면 결과 등급을 준다 (구조 시간·소실 정도·SOP 준수). 같은 판을 더 잘해 보고 싶게 만드는 장치다. 교육 내용(왜 그런가)은 G10에서 붙인다.

## 6. 조작 방식 (G3에서 비교표로 확정)

방향만 적는다. 목표는 **하나의 문법**이다.

- **누구(왼쪽 클릭) → 무엇·어디(오른쪽 클릭) → 그 대상에 할 수 있는 임무만 뜬다.** 스타크래프트·컴퍼니 오브 히어로즈·EMERGENCY의 공통 관례다.
- 역할에 맞는 임무가 기본값이다: 진압대가 불난 방을 오른쪽 클릭하면 '진압', 구조대는 '검색', 구급대가 환자를 오른쪽 클릭하면 '처치'.
- 지휘관 일(선언·보고·RIT·안전담당·전략)은 2단 메뉴에서 꺼내 **한 번에 누르는 지휘 단추**로 둔다.
- 대원이 멈추면 **머리 위에 이유**가 뜬다 ("진입 허가 대기", "문 잠김"). 누르면 바로 답할 수 있다.

## 7. 출동 단계 (G8에서 비교표로 확정)

SOP 200의 1·2단계를 그대로 따른다.

| SOP 200 원문 | 게임 |
| --- | --- |
| 1.1 출동지령을 정확히 청취한다 / 1.2 대상물 규모, 장소, 화재상황 및 출동로를 확인한다 | 지령 무전을 듣고 지도에서 대상·출동로 확인 |
| 2.1 상황실 무전청취 (각주: 유관기관 상황 및 조치사항 확인) | 달리는 동안 상황실 무전이 차례로 들어옴 (추가 신고, 건물 정보, 한전·가스 조치) |
| 2.2 현장상황 및 대상물 정보를 추가 파악하고 2개소 이상의 예비 소방용수를 선정한다 | 지도에서 소화전 2곳 고르기 (지금은 도착 뒤 카드) |
| 2.3 현장대응방안 모색 및 장비 선택, 필요시 추가 장비를 지원 요청한다 | 장비 고르기, 임무 미리 정하기, 지원 요청 (지금은 창 안 체크 상자) |
| 2.4 선착대는 육안으로 보이는 화재장소 주위의 상황을 무전으로 전파한다 | 도착 직전 보이는 상황 전파 → 최초 상황보고로 이어짐 |
| 3.1.1.1 차량 배치 | 도착 직전 배치 고르기 (지금 있음) |

출동 시간(현장 4분 = 실제 약 90초) 안에 못 고른 것은 도착 뒤에 하게 되고 그만큼 늦어진다.
